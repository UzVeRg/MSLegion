## INDEX-02 — Порядок дополнения базы

1. Считай весь существующий текст каждого файла в `docs/models/` неизменяемым префиксом. Сохраняй байты, кодировку, окончания строк, заголовки и порядок записей. Добавляй новый блок только после последнего байта файла. Это правило относится и к этому указателю.
2. Для каждого устойчивого факта укажи постоянный идентификатор пункта. Для каждого изменения добавь в конец того же файла запись с датой, целевым идентификатором, уникальным номером дополнения в этом файле, операцией и источником. Используй операции «добавление», «замена» или «отмена». Для нового пункта выбери новый идентификатор.
3. Восстанавливай актуальное состояние, применяя дополнения сверху вниз в порядке записи. «Добавление» вносит новый пункт, «замена» задаёт полный новый текст пункта, «отмена» выводит пункт из актуального контекста. Если правишь одно предложение существующего пункта, в записи «замена» всё равно приведи его итоговый текст целиком.
4. Для новой области создай отдельный Markdown-файл и добавь в конец этого указателя замену INDEX-01 с новым маршрутом. При изменении пути или ошибке в источнике добавь исправление к соответствующему пункту. Перед завершением сравни изменения с предыдущей версией и убедись, что diff существующих файлов состоит из добавлений в конце.

Шаблон записи в конце файла:

```markdown
## YYYY-MM-DD — D001 — NAV-02

- Операция — замена
- Текст пункта — полная актуальная формулировка NAV-02.
- Источник — `путь/к/файлу` и имя функции, раздела или ревизии.
```

## INDEX-03 — Что сохранять

Сохраняй краткие проверяемые факты, устойчивые маршруты и способы проверки. Значения секретов, содержимое `.env`, временные результаты и полные копии исходников оставляй за пределами базы. Используй источник рядом с каждым фактом. При расхождении кода и базы факт о поведении определяет код, а направление развития определяют командные документы.

Эта база хранит проектный контекст. Неизменный префикс рассчитан на повторное использование при одинаковом порядке загрузки. Фактическое использование кэша зависит от среды выполнения.
