# Тестирование backend

## Быстрые тесты

Обычный набор тестов не требует отдельной тестовой базы данных.

Из каталога `backend`:

```powershell
..\.venv\Scripts\python.exe -m pytest -m "not integration"
```

## Интеграционные тесты PostgreSQL

Интеграционные тесты используют отдельный PostgreSQL:

```text
127.0.0.1:5434
database: mslegion_test
```

Проверьте, что `TEST_DATABASE_URL` указывает на отдельную тестовую базу. Роль теста должна иметь право создавать схемы. Каждый сценарий создаёт собственную схему со случайным именем, устанавливает для соединений её `search_path` и удаляет только эту схему. Основной сценарий проходит путь от пустой схемы через `alembic upgrade head`, сравнение моделей с миграциями и HTTP-запросы до `alembic downgrade base`. Сценарий привязки Telegram проверяет обновление с прежней схемы, повторный и параллельный первый вход, отказ для неподтверждённых записей и подтверждение через административный API.

Сценарий пользовательских сессий использует подписанные тестовые данные Telegram и проверяет HTTP-вход, хранение хешей токенов, изоляцию профилей, истечение срока и отзыв при выходе. Настоящая пользовательская сессия из этого сценария также должна получить отказ на всех текущих административных маршрутах и на приёме событий.

Тесты лимита сессий проверяют шестой и параллельные входы. Пять действующих токенов дают доступ к профилю, вытесненный токен получает `401 invalid_session`, а сессии другого пользователя сохраняются. Миграционный тест проверяет выбор пяти сессий из прежних данных, включая совпадающие сроки окончания. Тест фоновой очистки проверяет предел в 500 записей за запуск, пропуск заблокированных строк и сохранение результата при сбое последующей обработки событий.

Сценарии сообществ проверяют конкурентное добавление участника и регистрацию одного адреса, изоляцию сообществ, доступ после исключения и разграничение операций владельца и участника.

Сценарий обработки статуса проверяет привязку ключа к источнику, дубликаты, откат записи статуса и внутреннего события при сбое, безопасный повтор, конкурирующую обработку и устаревшее наблюдение. Он сверяет показатели очереди, журнал администратора и статистику сообщества.

Сценарий публикаций проверяет доступ владельца и участников, ограничение размера и формата изображения, скачивание без кеширования и прекращение доступа после исключения из сообщества.

Сценарий квоты изображений одновременно загружает файлы в два сообщества одного владельца. Он проверяет границу общего объёма, отказ без потери прежнего файла, работу другого владельца и освобождение места после удаления. Снижение квоты в ходе теста проверяет работу с ранее сохранёнными вложениями.

Сценарий уведомлений проверяет явное согласие, адресата, параллельные вызовы доставки и отмену ожидающего уведомления при отключении. Ответы Telegram подменяются в автоматических тестах.

Из корня репозитория:

```powershell
docker compose up -d postgres-test
docker compose ps
```

Из каталога `backend`:

```powershell
$env:RUN_INTEGRATION_TESTS="true"
..\.venv\Scripts\python.exe -m pytest -m integration
Remove-Item Env:RUN_INTEGRATION_TESTS
```

Интеграционный тест запускает асинхронный сценарий через
`asyncio.SelectorEventLoop`, совместимый с асинхронным Psycopg на Windows.

## Полный прогон и CI

Из каталога `backend` с запущенной тестовой БД выполните команды ниже. Ожидаемый результат — Ruff и весь набор pytest проходят, интеграционный сценарий включён.

```powershell
..\.venv\Scripts\python.exe -m ruff check .
$env:RUN_INTEGRATION_TESTS="true"
try {
    ..\.venv\Scripts\python.exe -m pytest -q
} finally {
    Remove-Item Env:RUN_INTEGRATION_TESTS
}
```

При push и pull request [GitHub Actions](../../../.github/workflows/backend.yml) повторяет эти проверки на Linux с отдельным сервисом PostgreSQL 17 для каждой версии Python 3.12, 3.13 и 3.14.

## Тестирование Mini App

Из каталога `frontend` с Node.js 24.15 или новее в ветке 24 выполните команды ниже.

```powershell
npm ci
npm test
npm run build
```

Vitest проверяет пользовательские состояния с имитацией Telegram WebApp и HTTP-ответов. Проверка типов и сборка выполняются отдельно. [GitHub Actions](../../../.github/workflows/frontend.yml) запускает оба шага при push и pull request. Проверка в настоящем клиенте Telegram проходит после подготовки HTTPS-стенда.
