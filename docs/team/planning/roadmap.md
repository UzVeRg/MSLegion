# План развития MSLegion

Цель первого выпуска — пользователь открывает Mini App из Telegram, входит и видит свой профиль. Порядок ниже учитывает зависимости между backend, интерфейсом и развёртыванием. [Архитектурные решения](../architecture/overview.md)

## P0 — Основа и доступ пользователей

**Готово.** Служебные операции с пользователями требуют административный ключ. В CI проходят Ruff, миграции от пустой схемы и обратно, проверка соответствия моделей PostgreSQL и HTTP-сценарий с одновременной доставкой событий.

**P0.1 и P0.2 готовы на сервере.** Вход через Telegram привязывает проверенную личность к UUID и выдаёт отзываемую сессию. По сессии можно открыть собственный профиль и выйти. Прежние и вручную созданные записи требуют подтверждения администратором. Проверка полного сценария в клиенте Telegram входит в P1.

| Следующий шаг | Условие готовности |
| --- | --- |
| 1. Вход через Telegram и привязка личности — готово | Сервер проверяет подпись и время `initData` до чтения личности. Повторный вход возвращает тот же внутренний UUID. Учтены одновременный первый вход и существующие записи с неподтверждённым `telegram_id`. |
| 2. Сессия и собственный профиль — готово | Проверенный вход выдаёт отзываемую сессию. Профиль определяется её владельцем. Тесты покрывают истечение срока, отзыв, выход и изоляцию двух пользователей. |
| 3. Минимальные права — готово | Обычная сессия даёт доступ к своему профилю. Интеграционный тест подтверждает отказ на служебных маршрутах при предъявлении пользовательской сессии. Права на сообщества добавляются вместе с моделью членства. |

## P1 — Первый выпуск и основные модули

1. **P1.1 готово.** Оболочка Mini App на Vue подключена к входу и профилю. Тесты проверяют загрузку, истечение сессии, повторный вход и выход.
2. Подготовить тестовый HTTPS-адрес до проверки в клиентах Telegram. Настроить запуск Mini App через бота и пройти сценарий «открытие → вход → профиль» из Telegram. В клиентской сборке допустимы только публичные настройки.
3. До первого публичного выпуска проверить применение миграций при развёртывании, готовность API и восстановление PostgreSQL из резервной копии.
4. Реализовать сообщества и членство, затем регистрацию серверов и проверку прав участников на операции с ними.
5. Подключить первую предметную обработку сохранённых событий. Обработчик должен допускать повтор после сбоя без повторного применения эффекта. Перед подключением независимого отправителя привязать разрешённый `source` к его учётным данным.
6. Добавить Telegram-уведомления и административные операции для реализованных сценариев.

## P2 — Развитие продукта и эксплуатации

- Добавить статистику и аналитику.

- Добавить рейтинговые таблицы.
- Реализовать контент и медиахранилище.
- Расширить администрирование и мониторинг.
